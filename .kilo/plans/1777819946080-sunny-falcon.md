# Designer Agent Plan

## Goal
Create a "designer" agent that works as a Plan mode: collects information, asks clarifying questions, then requests user confirmation before moving to implementation/changes.

## Approach

### 1. Create the Designer Agent File
Create `.kilo/agents/designer.md` with the following characteristics:

**Frontmatter Properties:**
- `description`: A design-focused agent that gathers requirements, asks clarifying questions, and creates implementation plans before any changes are made
- `mode`: `primary` (user-selectable from the agent picker)
- `color`: A design-appropriate color (e.g., `#8B5CF6` - purple)
- `permission`: 
  - `edit`: deny (cannot make changes directly)
  - `bash`: deny (cannot execute commands)
  - `read`: allow (can read files to understand context)
  - `glob`: allow (can find files)
  - `grep`: allow (can search code)
  - `task`: allow (can delegate to subagents if needed)

**Prompt (markdown body):**
The agent should be instructed to:
1. Act as a technical design lead/architect
2. Gather requirements by asking clarifying questions
3. Explore the codebase to understand current state
4. Create detailed implementation plans
5. Present the plan to the user and request confirmation
6. Only after confirmation, suggest next steps for implementation (either switch to code agent or delegate)

### 2. Agent Behavior Flow
```
User Request → Designer Agent
    ↓
1. Understand the request
    ↓
2. Ask clarifying questions (if needed)
    ↓
3. Explore codebase (read-only)
    ↓
4. Create implementation plan
    ↓
5. Present plan + request confirmation
    ↓
6. On confirmation → suggest switching to code agent OR delegate via task
```

### 3. Key Design Decisions

| Decision | Rationale |
|----------|-----------|
| Read-only permissions | Ensures designer cannot accidentally make changes |
| Primary mode | User needs to interact with it directly |
| Plan-focused prompt | Mirrors built-in "plan" agent behavior but more structured |
| Confirmation step | Explicit gate before any implementation |

## Files to Create/Modify
- **Create**: `.kilo/agent/designer.md` - The designer agent definition
- **Create**: `design/` directory (if not exists) - where designer can write documents

## Implementation Steps
1. Create the `.kilo/agent/` directory if it doesn't exist
2. Write the `designer.md` agent file with proper frontmatter and prompt
3. Designer agent permissions:
   - `edit`: only allow `design/**` files
   - `bash`: deny
   - `read`, `glob`, `grep`: allow

# Web Module Modularization Plan

## Current State Assessment

### Current Structure
```
web/src/
├── main.tsx                    # Entry point
├── components/
│   ├── App.tsx                 # Root component (7 lines, just <h1>)
│   └── StatusBadge.tsx         # UI component consuming UserDto
├── pages/                      # Empty directory
├── services/
│   └── userService.ts          # Pure formatting function (misclassified as "service")
└── __tests__/
    ├── setup.ts                # jest-dom setup
    └── StatusBadge.test.tsx    # Tests for StatusBadge
```

### Issues Identified

| # | Issue | Impact |
|---|-------|--------|
| 1 | **Flat `components/`** — App root and UI components mixed together | No clear distinction between layout, page, and reusable UI components as app grows |
| 2 | **Misclassified `services/`** — `userService.ts` contains a pure `formatUser()` utility, not a service | Confusing naming; real API services will conflict with utility functions |
| 3 | **Centralized `__tests__/`** — Tests disconnected from the code they test | Harder to find related tests; doesn't scale with feature growth |
| 4 | **No hooks, types, utils, or constants directories** | No designated home for cross-cutting concerns |
| 5 | **No API client layer** | No HTTP client, no centralized error handling, no auth interceptors |
| 6 | **No routing or page components** | `pages/` is empty; no router installed |
| 7 | **No styling strategy** | No CSS files, modules, or framework |
| 8 | **Empty `public/`** | No static assets or favicon |

---

## Proposed Structure

A **feature-based modular** structure where code is organized by feature domain first, with shared infrastructure at the top level. This scales well while staying simple for the current small codebase.

### Target Structure
```
web/src/
├── main.tsx                        # Entry point (unchanged)
├── app/                            # App shell
│   ├── App.tsx                     # Root component with router/providers
│   └── App.test.tsx                # Co-located test
│
├── features/                       # Feature modules (add as features grow)
│   └── user/                       # Example: user feature
│       ├── components/             # Feature-specific components
│       │   └── StatusBadge.tsx
│       ├── services/               # Feature-specific API calls
│       │   └── userService.ts
│       ├── hooks/                  # Feature-specific hooks
│       ├── types.ts                # Feature-specific types
│       └── __tests__/              # Feature-specific tests (co-located)
│           └── StatusBadge.test.tsx
│
├── shared/                         # Cross-cutting shared code
│   ├── components/                 # Reusable UI primitives (Button, Input, etc.)
│   ├── hooks/                      # Shared hooks (useAuth, useFetch, etc.)
│   ├── services/                   # Shared infrastructure (apiClient, auth)
│   │   └── apiClient.ts            # Centralized HTTP client
│   ├── types/                      # Shared TypeScript types
│   ├── utils/                      # Pure utility functions (formatUser moves here)
│   │   └── format.ts
│   ├── constants/                  # App-wide constants
│   └── __tests__/                  # Tests for shared code
│
├── pages/                          # Route-level page components
│   └── HomePage.tsx                # Example page
│
└── styles/                         # Global styles and theme
    └── global.css
```

### Key Design Decisions

| Decision | Rationale |
|----------|-----------|
| **Feature-based modules under `features/`** | Groups related components, services, hooks, and tests by domain. Each feature is self-contained and can be understood/modified independently. |
| **`shared/` for cross-cutting code** | Prevents duplication. Only code used by 2+ features belongs here. |
| **`app/` separate from `components/`** | App shell (router, providers, layout) is infrastructure, not a reusable component. |
| **Co-located tests per feature** | Tests live near the code they test. Easier to find, easier to delete when removing a feature. |
| **`shared/utils/` for pure functions** | `formatUser()` is a utility, not a service. Services make API calls; utils are pure transformations. |
| **`pages/` for route-level components** | Pages compose feature components and handle data fetching for a route. Thin wrappers. |

### Module Boundary Rules

| Layer | Can Import From | Cannot Import From |
|-------|----------------|-------------------|
| `features/X` | `shared/`, `@api/*` | Other `features/Y` (no cross-feature imports) |
| `shared/` | `@api/*` | `features/`, `pages/`, `app/` |
| `pages/` | `features/`, `shared/` | `app/` |
| `app/` | `pages/`, `features/`, `shared/` | — |

### Migration Steps

1. **Install `react-router-dom`** — Add to `web/package.json` dependencies
2. **Create directory skeleton** — `app/`, `features/user/`, `shared/utils/`, `shared/components/`, `shared/hooks/`, `shared/services/`, `shared/types/`, `shared/constants/`, `styles/`
3. **Move & update `App.tsx`** → `app/App.tsx` with `BrowserRouter` + `Routes` wrapping
4. **Create `pages/HomePage.tsx`** — Stub page rendered at `/`
5. **Move `StatusBadge.tsx`** → `features/user/components/StatusBadge.tsx`
6. **Move `formatUser()`** → `shared/utils/format.ts` (rename from `userService.ts` since it's a utility, not a service)
7. **Move `StatusBadge.test.tsx`** → `features/user/__tests__/StatusBadge.test.tsx` (update import paths)
8. **Update `main.tsx`** — Update import path for App
9. **Update `vite.config.ts`** — Update `setupFiles` path if setup moves
10. **Remove empty directories** — old `components/`, `services/`, `__tests__/` (after migration)
11. **Verify** — run `npm test` and `npm run build` to confirm nothing breaks

### Router Setup (Included)

Install `react-router-dom` and wire up routing:

1. **Install** `react-router-dom` as a dependency in `web/package.json`
2. **Update `App.tsx`** to include `<BrowserRouter>` with route definitions
3. **Create `pages/HomePage.tsx`** as a stub page component rendered at `/`
4. **Update `main.tsx`** if needed (App already wraps router, so main stays the same)

```tsx
// app/App.tsx (sketch)
import { BrowserRouter, Routes, Route } from "react-router-dom";
import { HomePage } from "../pages/HomePage";

export function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<HomePage />} />
      </Routes>
    </BrowserRouter>
  );
}
```

```tsx
// pages/HomePage.tsx (sketch)
export function HomePage() {
  return (
    <div>
      <h1>Techs</h1>
    </div>
  );
}
```

### What NOT to Do Now

- **Don't add state management** — No state to manage yet; add when features require it
- **Don't add a CSS framework** — No styling requirements yet; choose when UI work begins
- **Don't over-populate `shared/`** — Only move code there when 2+ features actually need it
- **Don't create barrel `index.ts` files** — Premature for the current codebase size; add when import paths become deep

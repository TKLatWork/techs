# Module Interface Contracts

**Feature**: 002-project-structure
**Date**: 2026-05-31

## Overview

This project exposes internal module contracts that define how modules communicate. The `api` module is the contract layer bridging the Java backend (`app`) and TypeScript frontend (`web`).

## Contract 1: Java API DTOs (api module)

### Location

`api/src/main/java/` — Java source files defining interfaces and data transfer objects.

### Format

Standard Java classes/records with Jackson annotations for JSON serialization.

### Example

```java
package com.techs.api.model;

import com.fasterxml.jackson.annotation.JsonProperty;

public record UserDto(
    @JsonProperty("id") String id,
    @JsonProperty("name") String name,
    @JsonProperty("email") String email
) {}
```

### Rules

- All DTOs must be immutable (use Java records or final fields)
- All fields must have `@JsonProperty` annotations for explicit JSON naming
- DTOs may reference `domain` types for shared enums and value objects
- No infrastructure concerns (no Spring annotations, no database annotations)

## Contract 2: Generated TypeScript Types

### Location

`api/target/generated-sources/typescript/api-models.ts` — auto-generated by typescript-generator Maven plugin.

### Format

TypeScript ES module with interfaces matching Java DTOs.

### Example (generated from Contract 1)

```typescript
export interface UserDto {
    id: string;
    name: string;
    email: string;
}
```

### Generation Configuration

```xml
<plugin>
    <groupId>cz.habarta.typescript-generator</groupId>
    <artifactId>typescript-generator-maven-plugin</artifactId>
    <version>4.1.1</version>
    <executions>
        <execution>
            <id>generate</id>
            <goals><goal>generate</goal></goals>
            <phase>process-classes</phase>
        </execution>
    </executions>
    <configuration>
        <jsonLibrary>jackson2</jsonLibrary>
        <classPatterns>
            <classPattern>com.techs.api.model.**</classPattern>
        </classPatterns>
        <outputKind>module</outputKind>
        <outputFileType>implementationFile</outputFileType>
        <outputFile>target/generated-sources/typescript/api-models.ts</outputFile>
    </configuration>
</plugin>
```

## Contract 3: Maven Module Dependencies

### Parent POM (root)

```xml
<modules>
    <module>domain</module>
    <module>api</module>
    <module>app</module>
</modules>
```

### Module Dependencies

| Module | Depends On (Maven) | Depends On (npm) |
|--------|-------------------|-------------------|
| domain | — | — |
| api | domain | — |
| app | domain, api | — |
| web | — | api (via tsconfig path mapping) |

## Contract 4: Web ↔ App Communication

### Protocol

HTTP/REST (JSON payloads matching api module DTOs)

### Contract Enforcement

- `app` implements endpoints that accept/return types from `api` module
- `web` sends/receives JSON matching generated TypeScript types from `api` module
- Both sides share the same type definitions via the `api` module (single source of truth)
